# Pilot — 從可運作到有商業用途

## Synthetic correctness is not business proof
合成資料只能驗證計算、流程和錯誤處理。不能宣稱已提升毛利、改善轉換或替企業節省金額。

## Pilot setup
邀請 2–3 位可能使用此工具的電商／營運／財務人員，各自在授權且去識別的資料範圍內試用。先確認來源報表如何產生、費用是否含稅、平台費是否重複、退款入帳日、廣告通路歸屬。
第一輪不用先追求大樣本，重點是發現模型口徑和匯入流程是否能對應真實工作。

## Tasks
1. 與原有報表對同範圍 N 與明示成本後 CM。無法對齊時，記錄是來源、時間或定義差異；不調程式迎合未知數字。
2. 使用者不經口頭指引，指出最大貢獻下滑通路與兩項金額變化，並打開證據。
3. 使用者自行建立一個接受假設的情境，辨識「試算」與「預測」不同。
4. 產出一項願意在下一次營運會議採用的查核／實驗行動，寫下責任角色、預期檢查指標和停止條件。

## Measures to collect, not prefilled outcomes
資料整理／匯入時間、人工對帳差額、完成任務時間、理解錯誤數、可追溯建議數、人工修改量，以及使用者是否願意以自己的下一期資料再使用。
與原本試算表流程比較時，保持相同資料與問題，交替任务順序，記錄練習效應及人員差異。不預先填「節省 50%」或「營收提高」。
若工具算得正確但使用者花大部分時間手動整理 CSV，下一版先改善欄位 mapping／來源 adapter，而不是先加更多 AI 功能。
若退款、費用或共享廣告不符合 v1，先縮小適用範圍或開立下一版需求，不能暗中改口徑。
