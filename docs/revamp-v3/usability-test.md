## 0 隱私與紀錄原則

- 受試者與評審一律用代號（P1–P5、R1–R3）。姓名、聯絡方式、公司名稱只留在主持人自己的招募表，**不放進 repo**，也不寫進本文件或驗收文件。
- 測試只用示範資料與 `tests/fixtures/inclusive_tax/` 的合成含稅範例，不請受試者帶真實營業資料。
- 錄影、錄音要事先口頭取得同意；只用來回看計時與計數，報告只放整理後的數字與匿名摘錄。
- 盲評的錨點截圖（評審自行取得的公開產品文件截圖）**不放進 repo**。

## 2 測試前準備（主持人）

1. **環境**：
   - H1（v2）：正式站 `https://profitlens-tau.vercel.app`（v2.0.0）；若正式站已不是 v2，改用本機 `git checkout v2.0.0` 的 production build。
   - H4（v3）：受測版本所在的網址（preview 或正式站；部署需使用者當次同意，D-V3-24）。
   - 兩輪用同一種瀏覽器（Chrome 最新版）、同樣的視窗尺寸（依受試者裝置：1440×1000、1280×900 或 390×844）、清空網站資料（無 IndexedDB 工作區，等同新訪客）。
2. **檔案**：把 `tests/fixtures/inclusive_tax/` 的三份 CSV 放在受試者電腦的桌面資料夾「含稅範例」。
3. **答案鍵**（每輪測試前由主持人照當天畫面填寫，不憑記憶）：

   | 項目 | 答案（H1 v2） | 答案（H4 v3） |
   |---|---|---|
   | 本期扣廣告後貢獻（示範資料、預設期間） | | |
   | 差額方向與金額（比上期多／少多少） | | |
   | 三件事的第一件（標題與影響金額） | | |
   | 最大問題的「不利通路＋費用項＋金額」 | | |
   | 退款金額比最差的通路 | | |
   | 貢獻變化拆解中扣最多的兩項 | | |
   | 含稅匯入後本期淨營收（`inclusive_tax`：2,150.00） | 2,150.00 | 2,150.00 |

   參考（PRD 範例，以當天畫面為準）：扣廣告後貢獻約 127.0 萬，比上期少賺 59.9 萬；最大一項是折扣多花 118.8 萬。

## 4 A. 30 秒試用（30 秒試用完成率）

- **起點**：瀏覽器停在受測站首頁（新訪客狀態，未載入任何資料）。
- **指令**（照念）：「請在這個網站上找出三件事：本期扣廣告後貢獻是多少、比上期多或少多少、第一件要處理的事是什麼。說出答案後，請打開任何一個數字的計算來源看看。」
- **計時**：念完指令開始按碼錶；受試者說完三項答案**且**打開一次「計算與來源」抽屜（v2 是「看證據」按鈕開出的「怎麼算的」抽屜）時停錶。
- **完成**：30 秒內三項都正確、而且抽屜已開啟 ＝ 完成；超過 30 秒繼續讓他做完（記錄實際秒數），但不算完成。
- **目標**：5 人中 ≥ 4 人在 30 秒內完成。

## 5 B. 10 秒結論測試（10 秒結論率）

- **起點**：主持人先載入示範資料、停在經營總覽頁首（不捲動），把畫面蓋住。
- **指令**（照念）：「等一下畫面會出現 10 秒。請記住：扣廣告後貢獻是多少、比上期多或少多少、第一件要處理的事是什麼。」
- **流程**：打開畫面，計時 10 秒，蓋住；請受試者口頭說出三項。不得捲動、不得點擊。
- **判定**：三項全對才算這位受試者通過（依 §2 的判定標準）。
- **目標**：5 人中 ≥ 4 人三項全對。
- 每位受試者都要做 A 之後才做 B；A 已經看過答案的人，B 仍要做（測的是首屏是否一眼可讀），在結果表註記「A 後」。

## 6 C. 首個洞察時間（中位數）

- **起點**：新分頁、新訪客狀態。指令：「請載入示範資料，然後告訴我本期最大的問題出在哪個通路、哪一項費用、金額多少。」
- **開始計時**：受試者**按下載入示範資料按鈕**（v2「試試示範資料」／v3「載入示範資料」）的那一刻。
- **停錶**：受試者**第一次正確說出**「不利通路＋費用項＋金額」三者（金額依 §2 判定標準）。說錯不停錶，繼續計時。
- **上限**：5 分鐘；超過記為「> 300 秒」，算中位數時以 300 計並標註。
- **提示**：計時中若主持人提示，秒數照記，並在計數表註記提示次數。
- **彙總**：取 5 人的中位數。**目標**：≤ 45 秒，且比 v2 下降 ≥ 40%（v3 中位數 ≤ v2 中位數 × 0.6）。

## 7 D. 角色任務與評分（各角色任務成功率）

任務（PRD §3.4，同時是驗收腳本）：

| 角色 | 任務 1 | 任務 2 | 任務 3 |
|---|---|---|---|
| 老闆 | 說出本期賺賠與差額 | 說出最大的一個問題與金額 | 複製週會摘要（**v2 沒有這個功能，H1 基準改用「找到會議一頁摘要」**） |
| 主管 | 找出退款金額比最差的通路 | 從健檢列建立一筆待辦，並填好負責人與期限 | 在貢獻變化拆解中，說出扣最多的兩項 |
| 執行者 | 完成一份含稅 CSV 匯入（`tests/fixtures/inclusive_tax/`，金額基準選「含稅」） | 說出「扣廣告後貢獻」某一筆組成的檔名與行號 | 下載 Excel，並在裡面找到問題清單 |

**評分**（每項任務一格）：

| 結果 | 代碼 | 計入「成功」 |
|---|---|---|
| 不需協助就完成 | S | 是 |
| 主持人提示 1 次後完成 | H1 | 否（另記提示次數） |
| 提示 ≥ 2 次後完成 | H2+ | 否 |
| 放棄或 5 分鐘內未完成 | F | 否 |

- **成功率**＝S 的數量 ÷ 任務總數。整體目標 ≥ 90%，任一角色 ≥ 80%；每項任務主持人提示 ≤ 1 次。
- 每項任務另記完成秒數與觀察（卡在哪個畫面、說了什麼）。
- 執行者任務 1 的「完成」＝匯入成功且本期淨營收顯示 2,150.00（誤選「未稅」會是 2,257.50，算失敗）。
- 執行者任務 2 的「完成」＝說出的檔名與行號和抽屜顯示一致。

## 10 外部盲評流程（專業感與 AI 感，盲評）

**評審**：3 位（R1–R3），至少 1 位設計者、1 位電商經理人。H1 與 H4 最好同一批人。

**截圖**（每個版本 4 張，1440×1000 視窗、示範資料已載入、新訪客狀態）：
1. 經營總覽（首屏）
2. 通路健檢
3. 計算與來源抽屜（v2：「怎麼算的」抽屜），開在扣廣告後貢獻
4. 會議紀錄

v2 截圖用 tag `v2.0.0` 的 production build 擷取（可參考 `verification/revamp-R7/` 的同名畫面，但要重新擷取同一狀態）；v3 截圖在 V3-10 用同一份步驟擷取。

**去識別與隨機化**：
- 截圖裁掉網址列與瀏覽器外框；檔名改成隨機代碼（例如 `S3.png`），**不標版本**。
- 代碼與版本的對照表只由主持人保管，評分全部完成後才填進結果表；評分期間不給評審看。
- 每位評審的呈現順序各自隨機（例如用抽籤或亂數排序），把順序記在結果表。
- H1：評審看 v2 的 4 張。H4：評審看 v2、v3 各 4 張（共 8 張）混在一起隨機排序；以 H4 同一場次內 v2 與 v3 的評分比較為主，H1 的 v2 分數作為基準紀錄。

**錨點**：
- 開始評分前，請評審**自行**從公開產品文件取得 2–3 張截圖當作「專業財務工具」的參照（例如 PRD §4 的 Shopify Help Center 分析頁、Stripe 文件中的 Dashboard／Balance 報表頁），並先對錨點打分，讓量尺一致。
- 錨點截圖**不放進 repo**，也不交給主持人保存；結果表只記錨點來源的網址與評審給的分數。
- H1 與 H4 用同一套錨點（同網址）。

**評分**：每張截圖兩題 7 點量表，題目同 §8（Q1 專業感、Q2 AI 感），可附一句理由。

**目標**：v3 的 AI 感中位數比 v2 低 ≥ 2 分。
