# 04 匯入精靈與台灣來源規格

> 對應批次：R3。相關檔案：`src/components/import-panel.tsx`、`src/application/import.ts`、`import-guidance.ts`、`local-store.ts`、`workspace-backup.ts`、`src/domain/validation.ts`（**不改**）。資料契約以 `docs/DATA_CONTRACT.md` 為準：三份標準 CSV、日 × 通路（× SKU）粒度、未稅、TWD、Asia/Taipei。

## 1. 目標
- 有正確檔名的三份標準 CSV：**5 次點擊內**看到結果（選檔×1、下一步×2、確認口徑×1、套用×1）。
- 平台匯出是**含稅**時不再被擋：精靈內換算、記錄、可追溯。
- 同一來源第二次匯入不必重做欄位對照。
- 使用者不需要理解 manifest；日期、通路、涵蓋範圍由檔案提議，使用者只做確認。

## 2. 精靈四步（取代現在的單頁長表單）
```
Step 1 選檔      Step 2 對照欄位      Step 3 口徑與期間      Step 4 檢核與套用
[拖放三份檔案]   [每檔欄位對照表]     [含稅/未稅] [涵蓋] [兩期]  [問題清單] [套用]
```
### Step 1 選檔
- 三個拖放區（銷售、通路費用、廣告），接受 `.csv`；檔名含 `sales`／`cost`／`ad` 時自動歸位，可拖錯再換。
- 每區顯示：檔名、大小、列數、偵測到的欄位數、編碼（UTF-8／BOM）。超限（5 MiB／50,000 列）即時提示，不等到檢核。
- 下方「沒有檔案？」：下載三份範本（**含三列範例資料**，不只標題列）與一頁「怎麼從平台整理」說明連結。
- 隱藏進階：讀取 manifest JSON（保留給 v1 使用者）。

### Step 2 對照欄位
- （R3 實作註記）三份檔案欄名全部符合標準且沒有多餘欄位時，此步自動完成（步驟條標示「已自動完成」，可回上一步查看）；這是 §1「5 次點擊」的達成方式之一。
- 每檔一張表：來源欄名 → 標準欄位（下拉）→ 範例值（前 3 列）→ 狀態（已對照／忽略／必填未對）。
- 預選順序：① 標準英文欄名完全相同（現行）② **對照記憶**命中（§5）③ **來源預設**命中（§4）④ 中文欄名字典（§4.4）。任何非①的預選都以藍色標示「系統建議，請確認」；仍須使用者按「確認對照」。
- 未對照的多餘欄位列在「將忽略的欄位」，必須勾選「我知道這些欄位不會進入分析」。

### Step 3 口徑與期間
- **金額口徑**（必選）：`未稅`／`含稅（5% 營業稅，系統換算成未稅）`／`我不確定`。選「不確定」停在此步並顯示判斷方法（看發票／平台報表欄位說明）。
- 含稅時顯示換算範圍勾選（預設全勾）：銷售檔 `gross_sales`、`discounts`、`refunds`；成本檔 `cogs_net`（預設**不勾**，成本常為未稅進貨價，需使用者確認）；通路費用四欄（預設勾）；廣告費（預設勾，台灣媒體平台發票多含稅）。每個勾選旁一句說明。
- **涵蓋範圍與兩期**：由三檔日期自動提議（沿用現有 `import-guidance.ts` 的「從 CSV 提議範圍」）並**直接填入**表單，標示「由檔案提議，請確認」；資料截至日預設＝三檔最大日期＋1 天（可改）。比較方式預設等天數；若涵蓋 ≥ 2 個完整月，提供「整月比較」快捷。
- **通路**：由銷售檔 `channel` 唯一值自動列出（勾選即可，不再手打）。
- 兩個確認勾選維持：銷售涵蓋完整、金額口徑確認（文字改白話：「我確認這些是商品金額，不含消費者付的運費與平台補貼」）。（R3 實作註記）兩句列在同一顆「我確認口徑與期間，開始檢核」按鈕上方，按下即同時確認並進入第 4 步自動檢核；金額口徑沒有預設值。

### Step 4 檢核與套用
- 檢核結果：阻擋（紅）／待補（黃）／通過（綠）三段；每筆問題保留檔名、欄位、原始行號、原因（現行）。
- 「本次前處理摘要」：含稅換算（稅率、欄位、影響列數、換算前後合計）、對照來源（手動／記憶／預設）。
- 「套用」取代工作區（現行 `onCommit`），阻擋時不可套用、保留原資料（現行）。

## 3. 含稅換算規格（`src/application/tax-basis.ts`，新）
- 只在應用層做，domain 收到的已是未稅字串；`metric_version` 不變。
- 公式：`excl = incl ÷ (1 + rate)`，`rate` 預設 `0.05`，使用 decimal.js，**逐列**換算後 `ROUND_HALF_UP` 到 2 位小數再組回 CSV 字串。不做合計後再換算（避免與逐列加總不一致）。
- 空白保持空白；非數字維持原值讓 validation 報錯（不吞錯）。
- 保留原始列：`ImportSource` 新增 `raw_values`（換算前）與 `conversion: { basis: "inclusive", rate: "0.05", fields: [...], rows_converted: n }`；來源抽屜每列顯示「含稅原值 → 未稅換算值」。
- 匯出：分析 CSV 與 Markdown 的「資料範圍與口徑」加一行「含稅換算：5%，欄位 …」；備份 v4 保存 conversion（R4 升版時一併），v3 讀入時 conversion 為 null。（R3 實作註記）R3 的備份仍是 v3，不含 `conversion`／`raw_values`；還原後抽屜只顯示換算後值，資料頁沒有前處理摘要，R4 升 v4 時補。
- 測試（`tests/tax-basis.test.ts`）golden 手算：
  - `105.00` → `100.00`；`1.00` → `0.95`（0.952380… → 0.95）；`1050.37` → `1000.35`（1000.352380… → 1000.35）；`0.01` → `0.01`（0.00952… → 0.01）；`""` → `""`；`"abc"` → `"abc"`。
  - 三列合計：含稅 `105.00 + 210.00 + 1.00 = 316.00` → 逐列換算 `100.00 + 200.00 + 0.95 = 300.95`（不是 316/1.05 = 300.95…四捨五入 300.95，本例相等；另加一例證明逐列與合計後換算可差一分）。
- 稅率可調（0–20%，兩位小數），但 UI 預設 5% 且標示「台灣營業稅」。

## 4. 台灣來源預設（`src/application/source-presets/`，新）
目的：把常見平台／廣告匯出檔的**欄名**對到標準欄位，只做預選，不做自動彙總。

### 4.1 範圍與誠實標示
- 預設只提供「欄名對照字典」與「粒度提示」。**實際欄名以真實匯出檔為準**；本輪以「候選對照（待驗證）」交付，每個 preset 檔案頂部註記 `verified: false` 與驗證方法（用一份去識別化的真實匯出檔跑一次）。驗證通過後改 `verified: true` 並記錄日期與報表名稱。
- 偵測方式：比對標題列是否包含該 preset 的 2–3 個「指紋欄名」；命中才建議，且 UI 顯示「看起來像 ○○ 的匯出檔，已套用建議對照」。

### 4.3 訂單級 → 日 × 通路 × SKU 的彙總
本工具 v1 原則「不在 UI 自動猜收入、彙總訂單」維持。本輪交付：
- `scripts/aggregate_orders.py`（CLI，Phase 2 可改 TS）：讀訂單級 CSV ＋ 一份 `rules.json`（欄位對照、通路名、含稅、折扣分攤規則＝按商品金額比例、退款以退款日計），輸出三份標準 CSV ＋ `aggregation_log.md`（每條規則、丟棄列數、合計對帳）。
- 精靈 Step 1 偵測到訂單級檔案時，顯示「這是訂單明細，請先用整理工具彙總」並附腳本說明連結；不在 UI 內彙總。（決策 D5 若改為 UI 內彙總，另開批次。）

## 5. 欄位對照記憶（`src/application/mapping-memory.ts`，新）
- 鍵：`sha256(檔案角色 + 標準化標題列)`；值：對照表、preset id、含稅設定、最後使用日期。
- 存放：沿用 `local-store.ts` 的 IndexedDB，新 object store `mapping-memory`，**僅在使用者已同意本機保存時寫入**；未同意時只在本分頁記憶體。
- 讀取時顯示「上次（9/28）用過同樣欄位的對照，已帶入，請確認」，使用者仍要按確認。
- 「刪除本機資料」同時清除記憶；備份檔不含記憶（避免跨電腦帶錯）。
- 測試：同標題列不同順序視為同鍵；多一欄視為不同鍵。
