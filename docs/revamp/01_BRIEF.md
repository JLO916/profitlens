# 01 產品簡報（Revamp v2）

## 一句話
ProfitLens 讓台灣電商的行銷／營運主管，每週花 15 分鐘看清楚「營收漲了，扣完平台費和廣告到底多賺還是少賺、問題在哪個通路、下一步要做什麼」，而且每個數字都能追到來源。

## 現況定位 vs 目標定位
| | 現況（v1） | 目標（v2） |
|---|---|---|
| 主要讀者 | 懂會計口徑、能自己整理標準 CSV 的分析者 | 行銷／營運經理人、老闆；分析者是「幫忙匯入」的角色 |
| 進入點 | 匯入三份標準未稅 CSV | 從台灣平台／廣告匯出檔開始，精靈引導，含稅可換算 |
| 首屏 | 會議設定表單 → 摘要 → KPI | KPI → 本期三件事 → 趨勢與橋接 |
| 語言 | 行銷後貢獻、已入帳退款、履約費用、取分調整 | 扣廣告後貢獻、退款金額、物流與包材費、四捨五入差額 |
| 嚴謹性的呈現 | 每個區塊 1–3 句免責 | 一個「口徑說明」頁＋每頁一句；技術細節收合 |
| 使用節奏 | 一次性分析；重新整理即清空 | 週會／月會沿用；自動保存（經同意）；會議紀錄可比上次 |
| 輸出 | Markdown／CSV／JSON／列印 | ＋PDF、Excel、PPT 一頁式 |

## 目標使用者（三個 persona）
1. **行銷經理（主要）**：管廣告與促銷，每週要向老闆說明「廣告佔比與貢獻」；會用 Excel，不碰 CSV 口徑；開會前 10 分鐘要能產出一頁摘要。
2. **營運／電商主管（主要）**：管通路（官網、蝦皮、momo、PChome）與物流；關心平台抽成、退款、物流費佔比；要決定「哪個通路該加碼或止血」。
3. **財務／分析（支援）**：負責把平台報表整理成標準格式、確認口徑；重視追溯與對帳；是現有 v1 的既有使用者，功能不能退步。

## 設計原則（判斷衝突時的順序）
1. **先給答案，再給證據**：首屏是結論與金額；公式、行號、版本收在一層之下，永遠可開。
2. **一個名詞只有一個說法**：UI、匯出、口徑頁用同一套中文；技術代號只在「技術細節」出現。
3. **嚴謹不等於囉嗦**：限制與免責集中於「口徑說明」；頁面上每個區塊最多一句，且用白話。
4. **數字的方向一致**：紅＝對貢獻不利，綠＝有利；差額的正負以「對貢獻的影響」為準，排序用的原始差額收在細節。
5. **三次點擊內做到一件事**：載入示範、看三件事、建一個試算、加一個待辦，各自不超過三次點擊。
6. **台灣情境優先**：含稅、平台名稱、促銷檔期、去年同期是預設考量，不是例外。
7. **可持續使用**：資料與會議紀錄預設可保存（經同意），週會可比上週、月會可比上月與去年同月。
8. **財務核心零改動**：所有改善都在呈現層與應用層；domain 只做加法並有獨立 golden。

## 審查發現摘要（2026-10-02 實測正式站）
| 類別 | 發現 | 對應批次 |
|---|---|---|
| 首屏 | 總覽頁 KPI 卡在會議設定表單與摘要之下；1440×900 需捲動約 2 屏才看到 | R1 |
| 頁首負擔 | 7 頁都重複 AI 狀態橫幅、保存面板、期間列、下載列（約 500px） | R1 |
| 導覽 | 切頁後捲動位置不歸零 | R1 |
| 符號 | 「折扣率上升 +1,188,365」壞事顯示正數；「貢獻下降 −598,834」顯示負數 | R1 |
| 公式抽屜 | `CM_after = GP − P − Q − F − O − A` 無圖例；1,848 筆原始列分 50 頁 | R2 |
| 語言 | 會計名詞與工程名詞混用；免責句在單頁出現 10 次以上 | R2 |
| 匯入 | 3 檔＋manifest＋約 12 欄＋2 勾選才可檢核；含稅直接阻擋；每次重做對照 | R3 |
| 比較 | 只有前期 vs 本期；無去年同期、無目標達成率 | R4 |
| KPI | 無 ROAS／MER、廣告佔比、毛利率、售出件數的首屏呈現（MER 已在 domain 計算但未顯示） | R4 |
| 健檢 | 14 張卡中 7 張是同規則不同範圍；建議文字為模板 | R5 |
| 情境 | 點 4 次才到表單；首次計算顯示「版本 14」；只有相對 % 輸入 | R5 |
| 行動 | 執行狀態下拉異常高；期限是文字框；證據選取是 40 行原生 multi-select | R5 |
| 會議 | 會議設定與摘要混在總覽；無上次會議比較；無 PDF/Excel/PPT | R6 |
| 持續性 | 重新整理即清空；備份要手動下載 | R6 |
| 示範資料 | DTC／MARKETPLACE／SKU-001；台灣讀者無法代入 | R7 |
| README | 第一段是 commit hash 與測試數；非工程讀者 30 秒內看不出產品是什麼 | R7 |

## v2 成功指標（上線驗收用）
| 指標 | 目標 | 量測方式 |
|---|---|---|
| 首屏可見 KPI | 載入示範後，1440×900 與 1280×900 不捲動即可見五張 KPI 卡 | E2E 斷言 bounding box |
| 看到三件事 | 總覽頁捲動一屏內可見「本期三件事」 | E2E |
| 匯入到首個結果 | 三份檔名正確的標準 CSV：≤ 5 次點擊（含兩次確認） | E2E 計數 |
| 名詞覆蓋 | 每個 `MetricName`、`RuleCode`、導覽與主要按鈕都有 labels 條目；JSX 無散落中文指標名 | 單元測試＋grep |
| 免責密度 | 每頁免責句 ≤ 1 句（口徑頁除外） | grep 計數測試 |
| 試算 | 從情境頁到可填表單 ≤ 2 次點擊 | E2E |
| 待辦 | 從任一健檢項目到已建立待辦 ≤ 2 次點擊 | E2E |
| 會議輸出 | 一鍵產生一頁摘要（PDF）含三件事、通路表、決議、置頂行動 | 人工開檔 |
| 回歸 | 既有 golden／安全／匯出測試全部通過 | CI 命令 |
