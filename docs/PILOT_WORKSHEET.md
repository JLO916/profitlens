# ProfitLens 實務試用工作表

**狀態：待提供授權且去識別化的真實資料，尚未進行真實使用者試用。** 本文件是待填紀錄；空白不代表零、不適用或已通過。既有合成資料、Golden 答案、瀏覽器自動化耗時及工程測試結果，都不能填作本表的實務結果或商業效益證明。

每位試用者、每個資料快照各保留一份本表。僅使用匿名試用代碼及責任角色，不記錄姓名、客戶資料或機密帳密。試用資料留在獲授權的本機位置，不提交 Git、不放 `public`、不部署、不傳送模型。本輪以規則診斷完成任務。

依據：[試用計畫](PILOT_PLAN.md)、[資料契約](DATA_CONTRACT.md)、[指標口徑](METRICS.md)、[情境模型](SCENARIOS.md)。

## 二、準備三份標準 CSV 與資料設定

沿用既有範本，不另造格式：

- [sales_daily.csv](../templates/sales_daily.csv)：`date,channel,sku,category,units_sold,gross_sales,discounts,refunds,cogs_net,currency`。唯一鍵為日 × 銷售通路 × SKU；同一 SKU 的品類須一致。
- [channel_costs_daily.csv](../templates/channel_costs_daily.csv)：`date,channel,platform_fees,payment_fees,fulfillment_costs,other_variable_costs,currency`。唯一鍵為日 × 銷售通路。
- [ad_spend_daily.csv](../templates/ad_spend_daily.csv)：`date,channel,ad_spend,currency`。唯一鍵為日 × 銷售通路。
- [manifest.example.json](../templates/manifest.example.json)：可參考欄位在 UI 設定，JSON 可選讀。範例日期、通路及識別名稱都必須按本次資料確認，不得直接視為本次設定。

三檔須使用 UTF-8（可含 BOM）、逗號分隔及英文標準欄名。日期為 `YYYY-MM-DD`；金額是最多兩位小數的十進位字串，不含貨幣符號或千分位。幣別僅 TWD、時區為 Asia/Taipei。介面實作的每檔限制為 5 MiB／50,000 列；這是產品限制，不是處理速度保證。

| 需要逐項確認的規則 | 本次確認／異常紀錄 |
|---|---|
| 欄位映射：逐欄核對來源意義；不能依欄名猜收入或成本 | |
| 三檔唯一鍵、日期、幣別、通路及 coverage 範圍有效 | |
| `units_sold` 是非負整數售出件數，不扣退回件數、不估退貨率 | |
| `gross_sales` 是折扣前、退款前商品收入；已取消且未認列訂單排除 | |
| `discounts` 非負且不超過同列 `gross_sales`；未自行分配訂單級折扣 | |
| `refunds` 為當日已入帳退款，可來自前期，也可大於當日收入 | |
| `cogs_net` 是已入帳淨額，可因實際沖回為負；沒有依退款推算成本回沖、用單價補值 | |
| 成本空白維持未知；不得為了通過檢核填 0 | |
| 通路費用每個 coverage 日期 × 通路都有一列，確認無費用才填 0 | |
| 通路費用可含實際抵扣負值；`other_variable_costs` 未重複含廣告、商品成本或其他已列費用 | |
| 廣告每個 coverage 日期 × 通路都有一列，確認無投放才填 0；缺列不是零 | |
| 廣告 `channel` 為銷售目的通路，不把 Meta／Google 媒體名稱誤當銷售通路 | |
| 廣告非負；退款／跨期更正由來源端按一致政策整理 | |
| 共享廣告若無可靠歸屬，標為不支援範圍，不偷偷按營收分攤 | |
| 沒有銷售列僅在覆蓋已確認的日期／通路解讀為無銷售活動 | |
| 三檔前十列、未知欄位與檔名／行號已人工核對 | |

blocking（例如重複鍵、格式錯誤、混幣）時整批新資料不提交，原成功資料應保留。partial（缺成本、費用或廣告）可保留可計算的收入，但相關貢獻須為未知；不得把已知子集當作完整總額。記錄錯誤時保留檔名、欄位、行號、原因及修正依據，不為了顯示數字任意補值。

## 四、四個無口頭指引任務

交給試用者以下任務文字，觀察者不要示範操作。使用者需要協助時可提供協助，但須記錄提示內容、次數及是否因此完成；不能把受提示完成寫成獨立完成。安全或隱私問題可立即停止並記錄。

1. 匯入本次標準資料，與原有報表核對同範圍淨營收及明示成本後的行銷後貢獻。說明未對齊的差異，並找到至少一個數字的公式與來源。
2. 指出貢獻下滑最多的通路及兩項已觀察到的金額變化，開啟對應證據。若沒有下滑、費用不完整或無法比較，請說明此限制，不強找下滑結論。
3. 自行建立一個接受其假設的情境，說明條件試算與預測的不同，並說明調低廣告時對銷量的假設。不符合模型時辨識停用原因並記錄，不強行建立方案。
4. 建立並本機匯出一項願意帶到下一次營運會議的查核／實驗行動，填寫責任角色、期限、檢查指標、證據及停止條件。若尚不願採用，記錄原因。

## 五、情境假設適用性確認

Baseline 必須是本期單一完整通路，且符合 SCENARIOS 的非負成本與正收入等條件。負費用、純退款、缺漏可能仍適用實際金額診斷，但不因此適用情境。無法接受任一固定假設時記為「此方案暫不適用」，保留實際診斷。

| 固定假設 | 接受／不接受／未知及依據 |
|---|---|
| 平均牌價與商品組合固定，折扣前收入按售出量變動 | |
| 入帳退款金額比固定；它不是同批訂單最終退貨機率 | |
| 每售出量淨成本及退回結構固定 | |
| 平台費按原有效淨營收費率變動，無未建模最低費／階梯費 | |
| 金流費按原有效淨營收費率變動，無未建模最低費／階梯費 | |
| 履約成本按售出量及明填的單位成本變化重算 | |
| 其他變動費按售出量變動 | |
| 廣告由明填總支出變化控制，不推算銷量反應 | |
| 不含未輸入固定費、所得稅及其他未建模成本，結果不是公司淨利 | |

| 本次方案輸入／結果紀錄 | 待填 |
|---|---|
| 快照版本／本期／單一通路／baseline 貢獻 | |
| 方案名稱（最多三方案，各自從同一 baseline 計算） | |
| 銷量變化 v，相對百分比：−90% 至 +100%，必須明填 | |
| 折扣率變化 δ，百分點；新折扣率須介於 0 與 1（不含 1） | |
| 單位履約成本變化 f，相對百分比：−100% 至 +100% | |
| 廣告總支出變化 a，相對百分比：−100% 至 +200% | |

三個方案的改善額不能相加。敏感度 A／B／C 的銷量也須使用者明填，不指派機率；條件門檻不是銷量預測或公司損益兩平。敏感度分析目前不包含在方案、決策匯出或備份內，若用於討論須另記假設與範圍，不誤稱已匯出。
