# Product requirements — v0.1

## Product question
讓多通路零售／電商團隊在營運檢討時回答：營收增加但行銷後貢獻下滑，具體是哪些通路、商品毛利與費用項目造成金額變化？接下來應查什麼、測什麼？

## Users and workflow
主要使用者：電商營運主管。協作使用者：行銷及財務／營運分析者。
每次由使用者載入一個完整資料集，設定前後期與通路，檢查資料是否足夠，再閱讀可追溯的診斷，比較具明示假設的改善方案，最後匯出決策紀錄。

## First-release assumptions
一個企業、一個 TWD 幣別、Asia/Taipei 商業日期；展示集 84 天、DTC 與 MARKETPLACE 兩個通路、20 SKU。前後期預設各 42 天；允許相同天數比較，或各為單一完整自然月的比較；前期必須早於本期，完整月份不截天。金額合計與日均值分開呈現。
先服務具有商品銷售、商品成本、通路費用與行銷費的實體商品業務。美妝、生活用品、消費電子可在此口徑內更換品類；訂閱、服務業、製造成本會計與多幣別不是即插即用範圍。

## Screens
### 1. 資料工作區
按鈕「載入示範資料」「匯入標準 CSV」。上傳三份 CSV，加上資料集設定表單；表單可讀取 manifest.json，不要求非工程使用者手寫 JSON。
顯示前 10 列、每檔列數、日期範圍、費用口徑、資料截至日、完整性確認、欄位對照。只支援清楚的標準欄位或經使用者確認的對照，不做靜默猜測。
錯誤分 blocking / partial / warning；以檔案、欄位、CSV 行號提供可下載問題清單。
### 2. 經營總覽
本期／前期商品淨營收、商品毛利、行銷前貢獻、行銷後貢獻、貢獻率；84 天週趨勢；前後期行銷後貢獻金額拆解；通路比較。
圖表、表格、摘要、匯出必須共享相同 filters。所有金額可查公式與來源。資料不完整時，不顯示無標示的「總計」。
### 3. 診斷明細
通路異常與 SKU 商品毛利分開呈現。每個診斷包含事實、來源、金額範圍、資料限制、需要確認的假說及候選行動。點擊證據打開來源列／彙總明細。
只對通路呈現行銷後貢獻。SKU 只呈現商品毛利、折扣與退款金額，不製造 SKU 的媒體歸因。
### 4. 情境試算
以本期單一通路為基準；最多比較三個使用者命名方案。顯示銷量變化、折扣率變化、履約單位成本變化、廣告支出變化、一次性投入。每個輸入須明示；銷量變化不可由 AI 預設為零。
保留 baseline；顯示每項成本如何重算、假設與試算差額。實際成果欄不存在，以免誤認已發生。
### 5. 行動摘要
工作項目總數不受三項限制，最多置頂三個優先事項；各項可跨通路並綁定自己的原始期間／範圍，與情境固定假設分離。診斷可帶入未確認草稿，最後由使用者核對。每項含問題、fact IDs、具體動作、負責角色、驗證指標、期限、停止條件、所需額外資料。使用者可編輯和排優先。
支援本機下載 Markdown／CSV／JSON，附篩選、資料截至日、公式版本與假設。第一版不自動寄信、不執行廣告操作。

## Non-goals
不做通用 Chatbot、模型自行財務計算、自動調預算、預測銷量、多代理、登入權限系統、訂閱收費、正式電商／GA4／廣告 API 串接、多企業資料庫、外匯換算、完整 P&L、庫存補貨或客戶生命週期。

## Release requirements
M0–M6 關卡完成；golden 對帳與安全邊界測試通過；實際匯入不只接受內建示範；API 故障不影響核心計算。真實商業驗證依 PILOT_PLAN，不能用合成測試冒充已創造商業成效。
