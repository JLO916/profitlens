# 每日／每週／每月使用規格提案

本文件全部為下一版設計建議，不代表功能已實作、平台已串接或企業成果已驗證。

## 一、共同底座

1. **檢視不改變工作**：view filters、analysis data version、task evidence、meeting version 各自獨立。
2. **可說明的資料成熟度**：銷售、商品成本、平台費／物流費、廣告各自有涵蓋日期、讀取時間、已入帳／暫估／待補狀態。沒有新資料，不自動延長截至日。
3. **明確標準**：資料檢查通過不等於外部財務對帳完成；期間合計與日均不混用，率差用百分點。
4. **可恢復的會議**：保存資料、目標、範圍、討論方案、待辦、決議版本，與原始來源連結。

## 二、每日營運檢視

使用者問題：「昨天是否有需要今天處理的事？資料完整嗎？本月還差多少？」

### 首頁

- 先呈現「最新可用完整日期」，不是強迫以電腦今天當完整數據。
- 昨日／最近七日／本月至今，一鍵切換。昨日對上週同日；七日對前七日；本月累計對相同經過天數，完整月另選。
- 主指標：商品淨營收、廣告後貢獻（資料完整才呈現）、本月目標差額、廣告預算已用與剩餘。
- 今日最多三個優先處理問題；同一事件持續三日應更新一筆，不新增三張卡。
- 到期與逾期待辦、資料待補卡各自列出。

### 異常規則

- 金額重要性門檻、率差門檻、連續期數可由使用者明示設定。
- 資料不足用待補提醒，不列成經營惡化。
- 加入「營收與貢獻同時下降但費率不變」的測試。
- 合計、通路、商品的重疊金額不相加成可挽回收益。
- 先站內顯示，不急著外接 LINE／Email 推送；通知設定、頻率、責任人應先確立。

### 資料更新

建立來源設定檔：上次檔名模式、欄位對照、資料粒度、幣別／含稅口徑、通路別名及對帳確認規則。使用者可以修改後重新確認。

增量更新必須先預覽：新增列、修正列、不變列、疑似衝突。無資料列不代表刪除或零活動。訂單級資料與每日 SKU 彙總需分开入口；若新增轉換器，要保留訂單事件／退款入帳含義，不能對重複鍵直接去重。

## 三、每週營運會議

使用者問題：「本週偏離計畫在哪裡？上週決議做了沒有？哪三件事需要主管決定？」

### 一頁主報告

- **表現**：完整週實際、週目標、差額、上週同範圍、資料是否完整。
- **原因**：最大且不重複的三個貢獻變化；已觀察事實與待驗證解釋分開。
- **決議**：需要主管核准什麼、採用方案、替代方案、投入上限、風險條件、負責人與期限。
- **追蹤**：上週置頂行動狀態、未完成原因、本週要回報的結果。

全量資料及完整假設放附錄，不把二十筆待辦硬塞進一頁。為每場會議保留固定版本，現場查通路或商品明細不能改動會議既定選項。

### 決策卡範本

- 問題：哪個通路、哪個期間、哪個指標低於什麼標準？
- 證據：可點閱的兩至三項支持數字。
- 需核准事項：例如以明確上限進行一個折扣或物流條件試驗。
- 評估：方案假設、維持原貢獻所需條件、風險；不是保證收益。
- 追蹤：負責人、回報日、成功／停止條件、待補資料。
- 決議：核准／補資料再議／不採用、決議人與日期。

## 四、每月高層檢討

使用者問題：「是否達標？成長品質如何？下月資源怎麼配？哪些數字還會變？」

### 固定比較表

每個通路一列，列出：本月實際、月目標、差額、上月、去年同月、商品毛利率、廣告後貢獻及貢獻率。無去年資料時顯示無資料；不得用其他期間替代。目標與實際必須同一收入／费用口徑。

目標未設定不顯示達成率；目標為零或負值，以差額及是否跨越目標呈現，不用不穩定百分比。率差顯示「百分點」，例如 20% → 17% 為下降 3 個百分點。

### 預算與活動進度

- 收入目標、貢獻目標、廣告費上限由使用者輸入或正式計畫匯入，不把前期數字當目標。
- 線性進度僅在使用者選擇平均分攤時採用。
- 活動月可提供指定日期權重／每日計畫；活動名稱如 618、雙 11、雙 12、週年慶只是使用者設定例子，不宣稱平台已整合。
- `累計目標 = Σ 已經過日期的已確認每日計畫`；預算使用率與收入／貢獻達成率分開呈現。
- 月底數字外推必須標為基於指定假設的投影，不宣稱預測準確率。

### 關帳与重編

固定「會議使用版本」；費用、退款後補時新增重編版並列示差額與理由，不改寫上次會議記錄。速報／已對帳／已關帳需人確認、來源及時間；不是只按資料截至日推斷。

### 不要把貢獻擴充成假的公司損益

固定人事、公司費用、所得稅、現金流、應收帳款不在現有模型內。需要時另建明確的管理損益或結算資料層，不把「廣告後貢獻」重新命名為公司淨利、實拿金額或現金餘額。

## 五、所需資料實體（建議，不指定底層套件）

| 實體 | 最小欄位 |
|---|---|
| ImportProfile | 來源、粒度、欄位對照、金額口徑、通路別名、確認版本 |
| DataBatch | 來源角色、涵蓋日期、匯入時間、完整／待補／暫估、修訂號、來源 hash |
| TargetPlan | 期間、通路、指標、單位、目標、分日方法、分日權重、版本 |
| EvidenceReference | 不可變來源版本、指標、期間、通路、原始來源連結 |
| ActionItem | 行動 ID、證據、負責人、期限、執行狀態、置頂、進度與完成說明 |
| ReviewSession | 會議名稱、分析及目標版本、已選方案、置頂行動、重要性門檻、決議、核准狀態 |

## 六、不要憑現有資料生成的指標

目前主要輸入是銷售／成本／廣告彙總，不含完整訂單、客戶及流量識別：

- 客單價需要適當定義的訂單數，不能拿售出件數充當訂單數。
- 購買轉換率需要流量與轉換的同範圍、同口徑資料。
- 新客取得成本需要新客定義、去重與可歸屬支出。
- 媒體 ROAS 需要歸因轉換價值、視窗與媒體來源；不能用 MER 直接改名。
- 回購率需要可合法且適當處理的客戶／訂單歷史。
- 缺貨、庫存週轉與現金回款需要各自的資料層。

先完成貢獻、目標與行動閉環，再擴充上述指標。不要一次長成 ERP、CRM 與廣告投放平台。
