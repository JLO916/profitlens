# ProfitLens 第二輪檢核：從分析工具走向營運與管理會議

檢核日：2026-10-01（臺北時間）。部署版本、資料來源與限制見 `evidence_receipt.json`。

## 檢核邊界

本次成功讀取新版首頁 HTML、部署前端程式、主管摘要 CSS、Golden 合成資料與 AI 狀態。以轉錄的部署函式／表示式執行本機最小測試。直接 Chromium 導覽因 `ERR_BLOCKED_BY_ADMINISTRATOR` 失敗，未完成線上逐頁點擊、匯入、下載、保存／恢复、列印或手機畫面驗收。

證據類型：**L**＝抽取邏輯已執行；**S**＝部署程式／標記靜態確認；**R**＝產品改善建議，不是已發生的系統錯誤。

P0 表示正式週月會使用前先修；P1 表示下一批營運能力；P2 表示易讀與效率改善。本優先順序為審查判斷，不是產業統計排名。

## V2-01｜P0｜查看另一個通路，原行動就過期且鎖定（L + S）

**目前行為**：行動證據綁定 snapshot signature、revision、filter_hash。只改觀看通路就使 revision/signature 改變；所有既有 context 被重新標記 stale。stale 是黏著狀態，切回原範圍仍為 true。行動編輯 fieldset 因 stale 全部停用。

**已執行案例**：全部通路建立 context → 只改 DTC 篩選（同一 dataset_hash）→ 切回全部通路。結果為 false → true → true。參見 `logic_results.json`。沒有在 live React 頁面按鈕重現，需 E2E 補測。

**經理人影響**：會議中查明細後，原交辦不能直接更新；使用者必須複製文字、重選證據，容易產生重複工作。

**修正**：分開檢視範圍、原始證據版本、行動執行狀態。篩選只改 view；證據保持建立當時的期間與來源。來源資料真正改版時提示「引用較早版本」，但仍可改負責人、期限、進度。改綁證據應為明確操作並保留歷史。

**驗收**：切通路／日期／頁面再回來，任務不增加、不失去原引用，仍可更新進度；真實資料改版須顯示版本差異，不能偷偷換證據。

## V2-02｜P0｜主管摘要的決策設定不持久、範圍綁定過緊（S）

**目前行為**：摘要金額門檻及選取方案只在摘要元件狀態中，不在工作區備份。介面也明示切頁／重新整理要重设。敏感度三組輸入不在備份中。主管摘要接收全部行動，沒有以 pinned 篩為置頂三項。方案若 filter_hash 與摘要不同即失效／不可選，即使只是公司總覽要引用某單一通路方案。

**影響**：開會中下鑽再返回會議頁，會議設定可能變動；所有行動擠進摘要；DTC 方案不容易納入全公司回顧。

**修正**：獨立 `ReviewSession`：資料版本、目標版本、範圍、門檻、已選方案版本、置頂行動 ID、討論備註、核准狀態。保存／恢復此實體。可引用同一資料版本中範圍明確的通路方案，但各方案效果不得直接加總。摘要固定三項決策與三項追蹤，全清單附錄。

**驗收**：設門檻、選通路方案、置頂行動→離頁查資料→回來→保存／恢復→列印，內容一致且帶會議版本。

## V2-03｜P1｜自然月最後兩三天被當作週趨勢的一點（L + S）

**目前行為**：從每一期起日，每七天彙總；最後不足七天也顯示一個週點。八月為 7/7/7/7/3 天，九月為 7/7/7/7/2 天。顯示有備註，但折線仍把不同天數金額放一起。

**已執行案例**：沿用部署分桶邊界表示式；每日固定 1,000 的合成案例，完整週 7,000、月末 3,000 或 2,000。這是圖表判读風險，不是加總算錯或真實業績下降。

**修正**：月報預設每日線；週報採週一至週日。部分週應標天數、淡色／斷線、不納入完整週增減判斷。非連續月份或 YoY 不應畫成連續時間軸；用實際日期或對齊同一期間序列。

**驗收**：每日穩定案例不被描述成月末業績驟降；合計仍精確；空白與缺資料不畫成零。

## V2-04｜P1｜優先問題通過門檻的金額，與顯示／交辦範圍不同（L + S）

**目前行為**：同規則群組依成員最大絕對金額判斷重要性；primary 優先取「全部通路」，顯示 primary 金額並用它建立行動。

**合成邊界案例**：DTC 廣告費 +100,000、平台 -99,990，合計 +10；各自營收變化使合計與 DTC 的廣告占比規則均觸發。門檻為 1,000；群組因 +100,000 通過，但主文顯示合計 +10。已執行的是群組取 primary／門檻表示式，非完整規則引擎端到端。輸入非使用者真實資料。

**修正**：觸發門檻、排序、主標金額、證據與預設行動採一致 scope。可顯示「官網廣告費增加 10 萬；另一通路抵銷後合計僅增 10 元」。若選合計主標，門檻就使用合計。互相重疊的金額不得加成總改善機會。

**補強**：目前規則主要包含營收增／貢獻減與成本比率上升等；營收與貢獻同時下降、比率穩定且貢獻仍正的情境，可能沒有觸發重點。新增重要貢獻減少、目標缺口；判斷門檻由使用者設定，不虛構異常機率。

## V2-05｜P1｜有檔案保存，不等於有每日資料更新流程（S + R）

**現況**：本機單一手動保存槽；新的 CSV 主要是取代資料集。新匯入不等於沿用前次來源轉換設定；資料截至日是全域日期，未見各來源最後更新與關帳狀態。

**修正**：儲存匯入對照設定；更新前預覽新增、修正、不變列；按來源唯一鍵處理增量，不自動刪除缺列、不把缺列當零。保留舊批次及重編理由。費用延遲時顯示待補／速報，不用完整已入帳口吻。

**載入示範防呆**：清空已有提醒，但載入示範的 handler 未見等價的 dirty guard。實作共用「替換工作區」保護，涵蓋示範載入、匯入、開啟備份、清空，而非只有關頁。

**驗收**：任務／會議先保留；重複匯入不倍增；退款／费用回補只改受影響版本；所有覆寫入口一致提醒。

## V2-06｜P1｜資料已通過結構檢核，不等於完成平台／財務對帳（S + R）

**現況**：新版已有映射來源加總對照、口徑確認，應保留。但對照仍主要證明同批檔案的轉換一致；橋接加總一致更是內部算式恆等式，沒有獨立的外部控制總額。

**修正**：把「計算加總一致」「與匯入來源一致」「與平台報表／帳務控制總額一致」分成三種狀態。提供使用者輸入或匯入控制總額、差異理由、確認人與時間。

**重要**：勿自動把含稅、已扣退款的來源淨額逆推成原價收入。運費收入、補貼、折讓、固定費等若未納入，必須顯示缺口；毛利、貢獻、淨利、實收款不得混用。

## V2-07｜P1｜行動已有證據管理，還缺執行與成果追蹤（S + R）

**現況**：draft/confirmed/stale 管理的是證據／工作稿，不是實際待辦進度。未見未開始、進行中、待回覆、完成、取消的執行狀態與結果時間軸。

**新草稿內容瑕疵**：從診斷建立行動時，把診斷 limitations 串接放到 required_data；「非因果」「非淨利」等限制不是需要補交的資料。

**修正**：所需資料由規則明確定義，例如物流費明細、平台帳單、促銷條件；限制独立唯讀欄位。增加實際負責人、期限、執行狀態、阻礙、進度留言、完成後檢討，保持證據 immutable。

**驗收**：可以引用舊版證據回報本週完成；「完成」不自動等於效益已證實。

## V2-08｜P1｜月報缺少目標、預算與已結算／未結算層（S + R）

**現況**：摘要重心仍為前後期，未見目標／預算、月累計進度、前年同期比較捷徑、來源成熟度或關帳版本。

**修正**：先加使用者明示的月營收與貢獻目標、廣告預算、目標分攤方式、來源狀態；再加活動權重與版本化。目標未填顯示未設定，前期值不是目標。當貢獻目標為零或負，不顯示容易誤導的達成率，以差額顯示。

詳見 `OPERATING_REVIEW_SPEC.md`。

## V2-09｜P2｜新的資訊層增加，但首頁與數據表仍可簡化（S + R）

**現況**：主管摘要在原經營總覽之前，後方仍有 KPI、日均表、趨勢、橋接與通路圖表，資訊重疊；商品比較表約十四欄，前本期與差額未依同指標相鄰；純 SKU 無商品名稱。

**建議**：分「營運檢視」「會議檢視」，同一計算引擎。商品預設六到八欄，固定商品／通路欄；其他可選。增加選填商品名稱並保留穩定 SKU。金額可切元／萬元、主要百分比一位小數，來源維持精確；長公式與識別碼放進階。

**限制**：未完成 viewport／列印截圖，沒有宣称实际裁切、溢出、字體可讀性測量或頁數。

## V2-10｜P2｜AI 應以決策工作為目的，不是重複數字（S + R）

**現況**：公開 AI 仍為 PUBLIC_DEMO。新版已妥善收起不可操作的流程；模型資料仍以所選通路合計四十個指標事實為主，無法據此可靠定位各個通路原因。未做 live 模型品質測試。

**建議**：在受控環境新增有來源的通路別摘要、異常→查核問題→所需資料→行動草稿；不得自動核准。正式開啟時文案「經 ProfitLens 伺服器轉送」，不要把 Vercel 伺服器稱為使用者本機。

公開版以「規則分析可用；此展示版未啟用 AI」呈現即可；不建議僅為展示而開放無限制 API。

## 結論

新版已補出從匯入到摘要的主要元件。下一步不是繼續增加卡片，而是讓範圍切換不破壞任務、會議決策能保存、完整週與部分週不混淆，再建立目標／預算與更新追蹤。上述端到端行為仍須在可連線的真實瀏覽器中驗收，不能以本次單元式檢查代替。
