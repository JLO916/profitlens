# R3 來源預設驗證紀錄（第一階段：蝦皮、momo、91APP）

- 日期：2026-10-03
- 範圍：`shopee_orders`、`shopee_income`、`momo_settlement`（實為 momo 店+ 商店對帳明細）、`91app_orders`；Shopline／Cyberbiz／PChome／Meta／Google 留待後續。
- 方法：三位研究代理分別以 WebSearch／WebFetch 讀取各平台**公開**文件（官方賣家中心教育文章與欄位表圖片、momo 官方公告截圖、91APP 開發者 API 文件、ERP 廠商整合說明、公開的解析程式碼），重建各報表的標題列；三位懷疑者逐一開啟來源交叉查證（逐字確認／存疑／遺漏）。再以**去識別化合成樣本**（`tests/fixtures/source-samples/`：標題列依文件、資料列全為合成值，無真實個資或訂單）跑 `detectPreset`＋`suggestMapping`（`tests/source-presets-samples.test.ts`）與 `scripts/aggregate_orders.py`（`tests/aggregate-orders-platforms.test.ts`，手算比對）。
- 誠實標示：這些樣本**不是**真實匯出檔。preset 新增 `evidence` 等級：`public_docs`（官方文件／截圖重建）、`api_docs`（只來自 API 欄位說明）、`real_export`（真實檔驗證）。`verified` 仍一律 `false`；拿到任一份去識別化真實匯出檔後，跑同一條測試即可改為 `real_export`／`verified: true` 並記日期。

## 2. 樣本檔與測試
- `tests/fixtures/source-samples/{shopee_orders,shopee_income,momo_store_plus,91app_orders}.csv`＋`index.json`（每筆：檔案、preset、目標檔、預期對照）。個資欄一律遮罩（`buyer_a01`、`王○○`、`09********`、`台北市○○區○○路 1 號`），訂單編號為合成值；測試以正規式確認樣本不含電話／Email 樣式。
- `tests/source-presets-samples.test.ts`：每個樣本 `detectPreset` 命中正確 preset、關鍵欄位的建議對照正確、來源欄不重複使用、三份標準檔不會被誤判。
- `tests/aggregate-orders-platforms.test.ts`：三個樣本各以 `scripts/rules/*.rules.json` 實跑彙總腳本，逐列手算比對（蝦皮：單價 × 數量＋訂單層兩欄優惠券分攤；momo：單價 × 數量＋逐列折扣；91APP：列金額＋負數折扣取絕對值＋未稅成本），91APP 輸出並通過 `validateDataset`。
- 腳本新增 `unit_price`、`line_discount`、折扣欄陣列加總、折扣取絕對值（見 `docs/ORDER_AGGREGATION.md §8–§9`）。
